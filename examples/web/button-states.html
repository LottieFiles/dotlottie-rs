Button states — a state table of paint ops

One animated control, five UI states. Each state is a plain declarative record of paint values — scale, blur, grayscale, opacity, shadow — and a spring interpolates between them. This page is deliberately shaped like a future state machine: the state table below is the action list an SM would own.

state: enabled (hover / press the canvas)

What this shows

The whole-animation ops as a state system: hover lifts the control (drop shadow + scale), pressed compresses it, loading blurs and dims it, disabled drains color with a tritone ramp. Transitions are continuous — a spring drives every parameter toward the active state's targets, and effects are re-issued per frame (measured: free — ThorVG re-prepares effects on every update anyway).

The state table

const STATES = {
  enabled:  { scale: 1.00, blur: 0, gray: 0, opacity: 255, shadow: 0.25 },
  hover:    { scale: 1.05, blur: 0, gray: 0, opacity: 255, shadow: 1.00 },
  pressed:  { scale: 0.95, blur: 0, gray: 0, opacity: 255, shadow: 0.05 },
  loading:  { scale: 1.00, blur: 5, gray: 0, opacity: 215, shadow: 0.15 },
  disabled: { scale: 1.00, blur: 0, gray: 1, opacity: 150, shadow: 0.00 },
};
// per frame: spring params → targets, then
player.set_transform(around(256, 256, S(p.scale, p.scale)));
player.clear_effects();
if (p.gray > 0)   player.add_tritone(40,40,40, 128,128,128, 225,225,225, (1-p.gray)*255);
if (p.shadow > 0) player.add_drop_shadow(0,0,0, p.shadow*170, 90, 4+p.shadow*10, 4+p.shadow*8, 50);
if (p.blur > 0.05) player.add_gaussian_blur(p.blur, 0, 0, 50);
player.set_opacity(p.opacity);

State-machine shape

States own paint values; transitions interpolate them. The SM already has states, transitions and tweening for frames — this table is the same idea for paint props. A natural landing: state entry actions (SetOpacity, SetEffect…) plus transition-level easing/duration, reusing the existing tween machinery as the interpolation driver.
