Ink annotation — procedural shapes beside the Lottie

Overlay shapes are capi-owned geometry living in the same scene as the animation: draw on the stage and each stroke becomes a smoothed cubic path rendered above the running Lottie; the soft blob is the same API with below = true, z-ordered behind the art. Nothing here exists in the animation file.

draw on the stage

How it works

add_overlay(below) creates a retained shape in the wrapping scene and hands back an id; the shape mutates in place with set_overlay_path / fill / stroke / transform and needs no re-add per frame — the scene traverses its children on every update, unlike the Lottie picture (which skips when clean). Ownership stays with the scene: remove_overlay drops the last reference.

Pointer samples are smoothed Catmull-Rom → cubic, so each move event just rebuilds the current stroke's path buffers. Overlay coordinates are canvas pixels; overlays inherit scene-level opacity, effects, clip and blend by construction.

APIs used

const id = player.add_overlay(false);          // above the art
player.set_overlay_stroke(id, 5, r, g, b, 255);
player.set_overlay_path(id, cmds, pts);       // per pointermove

const bg = player.add_overlay(true);          // behind the art
player.set_overlay_fill(bg, r, g, b, a);
player.remove_overlay(id); player.clear_overlays();

State-machine shape

Overlay { id, path, style } — SM-declared decorations (selection rings, drop-zone highlights, badges) that live outside the animation file and react to state without touching the Lottie tree.
