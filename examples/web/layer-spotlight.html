Layer spotlight — hover isolates a layer

The pointer asks the renderer, not the DOM: hit_test resolves which named layer is under the cursor (tracking its live, animated bounds), and every other layer dims and softens. Move across the sun, clouds, and hills.

hover a scene element —

What this shows

hit_test(layer, x, y) works in canvas coordinates against the layer's oriented bounding box — it keeps tracking layers that the animation (or your own layer transforms) moves around. The spotlight itself is per-layer opacity plus a touch of per-layer blur on everything that isn't hovered.

Full-bleed layers like sky would always win a hit test, so the demo checks specific layers front-to-back and treats sky as "no hit".

APIs used

// front-to-back, first hit wins
const hovered = ["clouds", "sun", "hills-near", "hills-far"]
  .find((n) => player.hit_test(n, x, y));

for (const name of layers) {
  const dimmed = hovered && name !== hovered;
  player.set_layer_opacity(name, dimmed ? 140 : 255);
  player.set_layer_blur(name, dimmed ? 4 : 0, 50);
}

State-machine shape

The SM already keys pointer interactions on layer_name hit tests. Pairing that with SetLayerOpacity/SetLayerBlur actions gives "spotlight on hover" declaratively: onPointerEnter(layer) → state where the state's entry actions dim the other layers.
