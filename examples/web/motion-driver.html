Motion drives dotlottie — the real library, one tiny sink

This page imports the actual Motion engine from a CDN and points its reactive value graph at Lottie layers instead of the DOM. One ~20-line layerEffect sink — the analog of Motion's own propEffect — and suddenly springValue follows, animate() sequences, press() gestures and scroll() parallax all drive the blobs. Zero renderer changes: Motion is just another host for the per-layer API.

The sink

Motion's propEffect binds motion values to any JS object — it's how Motion drives Three.js. layerEffect is the same shape for a Lottie layer: subscribe to each channel, and on change schedule one matrix write in Motion's frame.render phase (the queue dedupes, so N channel updates collapse to one write per frame). The write composes over the animated base — the idle float keeps playing underneath, because per-layer props re-compose onto the freshly-built layer every frame. 

function layerEffect(player, layer, ch) {
  const apply = () => {
    const base = player.get_layer_transform(layer);
    if (!base) return;
    setLayerT(player, layer, mul(
      T(ch.x?.get() ?? 0, ch.y?.get() ?? 0),
      around(base[2], base[5],
        mul(R(ch.rotate?.get() ?? 0),
            S(ch.scale?.get() ?? 1, ch.scale?.get() ?? 1)))));
  };
  const stops = Object.values(ch)
    .map((v) => v.on("change", () => frame.render(apply)));
  apply();
  return () => stops.forEach((s) => s());
}

What's driving what

Pointer → springValue per blob (velocity-carrying follow) → transformValue scales it by depth. The strip's scroll() progress → springValue smoothing → mapValue per-depth drift. press() hit-tests with hit_test_precise, squashes the blob's scale value, and the returned end-callback restores it — bouncy if info.success, flat if the press was cancelled. The button fires an animate() sequence with relative at: "<+0.08" offsets — a spring-eased spin wave.

Why this matters

Motion's whole ecosystem is a host driver for this surface. Springs, sequences, stagger, gestures, scroll — none of it needs reimplementing in Rust. The runtime keeps what must work without JS (the state machine); the browser gets Motion's DX today.
