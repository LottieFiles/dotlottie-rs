Path clip morph — designer shapes as clips

The clip is no longer limited to rects and circles: any bezier path — copied straight out of a design tool as SVG path data — can gate what's drawn. Here a heart authored as a d string clips the scene, and because both shapes share one command layout, dragging the slider lerps the control points into a circle: a live path morph, one set_clip_path call per change.

heart ↔ circle

How it works

parseSvgPath (≈50 lines of JS) turns the SVG path data into the two flat buffers ThorVG's tvg_shape_append_path wants: a command array (Close / MoveTo / LineTo / CubicTo) and an interleaved point array. That's the whole boundary — no path type crosses into Rust, just bytes and floats.

The heart is six cubics; the circle is generated with the same six-cubic layout, so morphing is a plain lerp over the point arrays. Scene clips are canvas pixels, and ThorVG frees the old clipper on every replace, so per-frame morphing is just calling the setter again.

APIs used

const { cmds, pts } = parseSvgPath("M 256 464 C 130 366 …Z");
player.set_clip_path(cmds, pts);   // canvas px
player.clear_clip();

State-machine shape

SetClipPath { path, tween } — the path lives in the SM config as plain SVG data (designer-authored); compatible layouts tween point-wise, exactly like this slider.
